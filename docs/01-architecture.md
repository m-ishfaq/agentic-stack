# 01. Architecture

## The model

Three layers, one direction. Nothing is edited twice.

```text
source of truth        generated              enforced
.agents/ + config  ->  tool adapters      ->  hooks + CI
```

1. **Source.** `.agents/` and `AGENTS.md`. Hand-edited, reviewed like code.
2. **Adapters.** Tool-native files generated by the CLI. Committed, marked generated, never hand-edited.
3. **Enforcement.** Hooks inside the tool, plus the same scripts in CI. CI is authoritative.

## Why adapters are committed

If generated files are gitignored, every teammate must run the CLI before their agent works, and every cloud agent sees an empty repo. Committing them means zero setup for the team. The cost is drift, so CI fails when generated files do not match the source.

Rules for generated files:

- First line: `<!-- generated by agentic-stack vX.Y.Z, edit .agents/ instead -->` or the comment form for the format.
- Written only by `agentic sync`.
- Hash recorded in `.agentic/lock.json`.
- If a human edits one, `sync` refuses to overwrite it and reports drift.

## Install algorithm

```text
1. Read flags and detect the project
   lockfiles, manifests, stacks, existing tool folders
2. Ask only what detection cannot answer
   adapters, strictness, packs, test command override
3. Build a plan in memory
   every file, its source template, rendered content, and hash
4. Resolve existing paths per file
   managed block, import line, JSON union, skip, or --force with backup
5. Write atomically
   backup to .agentic/backups/<timestamp>/ before a replacement
6. Write .agentic/lock.json and agentic.config.json
7. Print next steps, including the one manual action: git add
```

The CLI never runs `git add`, `git commit`, or `git push`. It prints the exact commands for the human.

## Configuration

`agentic.config.json`, committed, validated with a schema.

```json
{
  "$schema": "https://agentic-stack.dev/schema/v1.json",
  "version": 1,
  "project": {
    "name": "acme-api",
    "packageManager": "pnpm",
    "commands": {
      "install": "pnpm install",
      "dev": "pnpm dev",
      "test": "pnpm test",
      "testSafe": "node .agents/scripts/test-safe.mjs",
      "lint": "pnpm lint",
      "typecheck": "pnpm typecheck",
      "build": "pnpm build"
    }
  },
  "adapters": ["agents-md", "claude", "cursor", "copilot"],
  "packs": ["typescript"],
  "policy": {
    "strictness": "strict",
    "scope": "project",
    "allowHome": false
  },
  "budgets": {
    "agentsMdLines": 150,
    "alwaysOnTokens": 2000,
    "ruleLines": 40
  }
}
```

Unknown keys are an error, not a warning. A typo in a deny list must not silently weaken the policy.

## Detection

| Signal | Result |
|---|---|
| `pnpm-lock.yaml`, `package-lock.json`, `yarn.lock`, `bun.lockb` | package manager |
| `package.json` scripts | test, lint, typecheck, build commands |
| `tsconfig.json`, `*.ts` | typescript pack |
| `next.config.*`, `react` in deps | react-next pack |
| `pyproject.toml`, `requirements.txt`, `uv.lock` | python pack |
| `go.mod` | go pack |
| `composer.json` with `laravel/framework` | php-laravel pack |
| `pom.xml`, `build.gradle` | java pack |
| `Cargo.toml` | rust pack |
| `Dockerfile`, `compose.y*ml` | docker pack |
| `turbo.json`, `nx.json`, `pnpm-workspace.yaml` | monorepo pack |
| `pubspec.yaml`, `*.xcodeproj` | mobile pack |
| `.env` present | warn: confirm it is gitignored, never read values |

Detection never reads `.env`, never reads secret files, and never sends network requests.

## Rendering

- Templates use `{{variable}}` only. No logic in templates.
- Conditionals are resolved before writing, so the output is plain text.
- Every generated file gets a header and a stable trailing newline.
- Line endings are LF. `.gitattributes` enforces it.
- Budget checks run after render. Over budget fails `sync` unless `--allow-budget-overrun`.

## Adapter contract

Each adapter exports:

```ts
interface Adapter {
  id: string;
  detect(): boolean;
  outputs(ctx: RenderContext): OutputFile[];
  permissions(policy: Policy): PermissionMap | null;
}
```

`OutputFile` is `{ path, content, mode? }`. Adapters never read the filesystem directly; everything comes from the render context. This keeps generation testable with fixtures.

Adapter rules:

- Never write outside the project root.
- Never overwrite a file whose hash does not match the lock.
- Never emit a secret.
- Skip silently when the tool is not selected.
- Report the tool name and file count to the CLI.

## Policy compilation

One policy, many syntaxes.

```text
.agents/policies/deny.json
        |
        +-- Claude  .claude/settings.json   permissions.deny, hooks
        +-- Cursor  .cursor/rules/00-policy.mdc + .cursor/mcp.json
        +-- Copilot .github/copilot-instructions.md section
        +-- Codex   AGENTS.md section
        +-- Gemini  GEMINI.md section
        +-- CI      .github/workflows/agentic.yml
```

Only Claude and Cursor have real permission primitives today. For the rest we generate explicit instructions plus the hook scripts, and CI runs the checks. The policy file is the single place to change behavior.

## Drift

`agentic check` fails when:

- a generated file is missing
- a generated file's hash differs from the lock
- a source rule changed but `sync` was not run
- the lock version is older than the installed CLI and `upgrade` is required
- a required policy entry was removed
- a protected path is not ignored by git

This runs in CI on every pull request. Drift is a build failure, not a warning.

## Context budget

| Artifact | Budget |
|---|---|
| `AGENTS.md` | 150 lines |
| each rule | 60 lines |
| always-on total | about 4,000 tokens |
| skill description | 1,024 characters |
| skill body | loaded only on demand |

`AGENTS.md` is a router. Details live in rules and skills. If a rule is not needed for most tasks, it becomes a skill.

## Failure behavior

- Missing template: error with the expected path.
- Invalid config: error with the offending key.
- Collision: skip, report, exit 1. `--force` backs up first.
- Permission denied: error, no partial writes.
- Unknown adapter: error listing valid adapters.
- Network failure: no network is required after install, so this should not occur.

## Non-goals

- Running the project's build or tests during install.
- Managing secrets.
- Replacing the language's formatter or linter.
- Being an agent runtime. We configure agents, we do not ship one.
